### 特性

- **全平台适配**：兼容所有平台浏览器，修复上游开源版无法在 iOS 长按的问题，优化交互。
- **开箱即用**：默认用 SQLite，不需要额外跑一个数据库服务；容器首次部署后浏览器打开就是安装向导。
- **低配友好**：默认 Web 服务并发参数专为低配服务器优化，参数都可以通过环境变量单项覆盖。
- **安全加固**：登录/注册等认证接口增加限流，不采信客户端伪造的转发头，移除了 SVG 上传，并淘汰了一批带 CVE 的依赖。
- **界面清爽**：整套前端 UI 重做，简洁风格 + 亮色/暗色/跟随系统。深度优化手机端查看图片的手势操作体验。
- **图库功能**：新增**图片标签、图片编辑、全屏模式**多项功能。
- **批量导出**：登录用户在【用户设置】可按相册 / 标签 / 上传日期 / 存储策略筛选，把自己账号下的图片流式打包成单个 zip 下载（原图）。

## 快速开始

Docker Compose（推荐）：

```yaml
services:
  lsky-pro:
    image: ghcr.io/mole404/lsky-pro-docker:latest
    container_name: lsky-pro
    restart: unless-stopped
    ports:
      - "127.0.0.1:8089:8089"                 # 主机端口:容器端口（WEB_PORT）
    volumes:
      - $PWD/lsky-pro/data:/var/www/html      # 站点数据全在这个目录里（$PWD = 你执行 compose 时所在的目录）
    environment:
      - WEB_PORT=8089
```

或使用等价的 `docker run`：

```bash
docker run -d --name lsky-pro --restart unless-stopped \
    -p 127.0.0.1:8089:8089 \
    -v "$PWD/lsky-pro/data:/var/www/html" \
    -e WEB_PORT=8089 \
    ghcr.io/mole404/lsky-pro-docker:latest
```

容器挂载卷路径可按你的实际情况改（上例是 `$PWD/lsky-pro/data`，`$PWD` 就是你执行命令时所在目录）。  
上面把端口只绑到 `127.0.0.1`：生产环境推荐这样，再在前面放一层 Nginx 反代来终结 TLS，容器本身不用直接对外。

### 全新安装

1. 容器首次部署后访问 `http://<主机>:8089/`，会自动跳到安装向导，**更推荐设置反代访问**
2. 按向导填写数据库（默认 SQLite，路径可留空）与管理员账号密码
3. 安装完成，开始使用

### 正在使用开源版 Lsky-Pro V2.1？ 从上游开源版无损升级

1. docker stop 旧容器名（如 lsky-pro）
2. **完整备份数据目录（必做，别嫌麻烦）**
3. docker rm 旧容器名（如 lsky-pro）
4. 根据旧版容器数据挂载路径，编辑新容器挂载卷路径，新版与上游旧版读取路径完全相同，**务必确保挂载卷与旧版容器一致，挂载错误进去会报 500（数据不会丢，只是读取失败）**
5. 容器挂载卷路径设置正确后，拉取本仓库镜像部署即可完成升级

## 常见配置

### 端口

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `WEB_PORT` | `8089` | 容器内 Web 服务的 HTTP 端口 |
| `HTTPS_PORT` | `8088` | 容器内 HTTPS 端口（自签证书，仅供内网调试，一般不用，非公网 HTTPS 访问用途！） |

自签证书不随镜像发放、也不进数据卷：每个容器首次启动自己生成。想用自己的证书，把 `.crt` / `.key` 挂到容器内 `/etc/apache2/ssl/lsky-selfsigned.crt` 与 `.key` 覆盖即可。  
⚠再次提醒，这个自签证书只服务容器内 Apache 的 443 vhost，不是公网 HTTPS 访问用的！不是拿来反代用的那个 CA 证书！

### 并发与内存

镜像默认内置一套面向小内存单用户的参数。每一项都能用环境变量单独覆盖：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APACHE_START_SERVERS` | `2` | 启动时预建的子进程数 |
| `APACHE_MIN_SPARE_SERVERS` | `1` | 空闲子进程下限 |
| `APACHE_MAX_SPARE_SERVERS` | `3` | 空闲子进程上限 |
| `APACHE_MAX_REQUEST_WORKERS` | `5` | 并发请求上限（内存占用的主要来源） |
| `APACHE_MAX_CONNECTIONS_PER_CHILD` | `5` | 单个子进程处理多少个请求后回收（`0` = 永不回收） |
| `APACHE_KEEP_ALIVE` | `Off` | 只接受 `On` / `Off`；`Off` 最省内存 |

如果您不知道这些参数起什么作用，请不要随意修改，否则有爆内存风险。  
面向个人自用以上参数保持默认值即可，多用户场景下可增大。

## 用户端图片批量导出

登录用户在【用户设置】页面可按条件筛选，把自己账号下的图片**流式打包成单个 zip** 直接下载。导出的是**原图**（不转码、不加水印、不做任何客户端处理）。

点击「打包下载」会先弹确认框，显示本次命中的**张数与预估体积**，确认后才开始下载；导出结束后设置页会给出本次结果（张数 / 体积 / 是否有失败；中途中断则显示到中断为止已完成的张数）。

### 筛选条件

| 维度 | 说明 |
| --- | --- |
| 相册 | 可多选；**「未分类」是显式选项**，对应没有相册归属的图片 |
| 标签 | 可多选，选项后带该标签下的图片数量 |
| 上传日期 | 闭区间，可只填一端；按**上传时间**判断，时区取应用自身时区（本镜像默认 `PRC`，即北京时间） |
| 存储策略 | 可多选 |

- **一个都不选 = 导出自己的全部图片。**
- 维度之间是 **AND**，维度之内是 **OR**；**例外：标签维度之内是 AND**（所选标签必须全部命中）。
- 例：「素材」∪「表情包」相册 **且** 带「风景」标签 **且** 上传日期在某区间 **且** 策略为 A ∪ B。
- 无论怎么组合，导出范围永远只限当前登录用户自己的图片，不会越权取到别人的图。

### 包内结构

```
<相册名>/<原文件名>         # 按相册分目录；同名文件自动加后缀区分
uncategorized/<原文件名>    # 未分类的图片
_index.csv                  # 清单
_export_summary.txt         # 本次摘要
_export_failures.txt        # 仅当有图片导出失败时才出现
```

- `_index.csv`：文件名 / 字节大小 / 上传时间 / 相册 / 标签 / 策略 / 直链 / key。
- `_export_summary.txt`：导出时间、筛选条件（人话描述）、图片张数与成功 / 失败数、总字节数、索引与失败清单的文件名。
- `_export_failures.txt`：每行「图片 ID + 失败原因」，**不含**存储路径、链接或任何凭据。个别图片读取失败不会中断整包，只会被跳过并记在这里（读到的文件为空时也会单独标注）。

### 硬限制

- **不支持断点续传。** 单请求流式输出，zip 的中央目录写在最后，响应也没有 `Content-Length` / `Range` 支持 —— 中途断线、关闭或刷新页面都只能**重新导出**一次（`wget -c` / `curl -C -` 同样不行）。
- **耗时受部署机上行带宽限制。** 服务端要把整批图片从远端存储逐个读出来再转发给浏览器，图片多或体积大时下载会比较久；请预留时间、保持网络稳定。浏览器侧可能留下未完成的半截下载文件，需要自行清理。
- **同一账号同时只能有一个导出任务**，第二个请求会被拒绝（HTTP 429）。另有一个按机器规模自动计算的**全局并发上限**（按 Web 并发进程数取 `min(4, max(1, 进程数 / 2))`，本镜像默认 5 个工作进程 ⇒ 2），可用环境变量 `EXPORT_MAX_CONCURRENCY` 覆盖。
- **是近似快照。** 遍历期间若在别处删除图片或改动相册归属，可能少一张或进失败清单。
- 几万张 / 几十 GB 量级建议自行分批导出。

### 零落盘与反向代理

导出过程**不在容器内写任何临时文件**：图片是「从存储读一块 → 立刻写进 HTTP 响应一块」，不落盘、不压缩、不在服务端缓存整份内容。导出全程只读 —— 不写数据库任何一行，也不改动任何已存的图片。

响应头里带了 `X-Accel-Buffering: no`，nginx 收到后会关闭该响应的缓冲，不会把导出内容缓冲到临时文件。**绝大多数部署不需要改反代配置。**

只有当你的反代配置里显式写了下面这行（即让 nginx 无视该响应头）时：

```nginx
proxy_ignore_headers X-Accel-Buffering;
```

才需要在该站点对应的 `location` 里手动补上：

```nginx
proxy_buffering off;
proxy_max_temp_file_size 0;
```

用 php-fpm 而非容器内 Apache 部署时同理，给 `fastcgi_buffering off;`。

站点在 Cloudflare 后面时另需注意：Cloudflare 免费 / Pro / Business 的**首字节超时固定为 125 秒，不可调**（只有 Enterprise 能改），超时会被判为 524。因此导出路径上刻意不做耗时统计类操作（张数 / 体积的计算已前置到点确认框那一步），保证首字节尽快返回。另，Cloudflare 不限制响应体大小（512MB / 5GB 是它缓存内容时的上限，导出不属于会被缓存的内容）。

### 导出自身的服务端痕迹

导出在设计上不给机器留垃圾，所有痕迹都有明确的生命周期：

| 物件 | 生命周期 |
| --- | --- |
| 并发占位表（同一账号唯一 + 全局并发上限共用一张表） | 正常结束或取消**立即删除**；心跳每导出一张图刷新一次，超过 5 分钟没心跳即视为已死并回收（进程被强杀时最坏 5 分钟自愈），整张表另有 900 秒兜底过期 |
| 导出结果记录 | 30 分钟后自动过期（设置页据此显示「上一次导出」的结果） |
| 应用日志 | **导出成功不写任何日志**；仅在有失败 / 异常时写 1 条，落在 `storage/logs/export-YYYY-MM-DD.log`，超期 3 天自动删除 |
| 临时文件 | 无（流式设计） |
| 数据库 / 图片 | 只读：不写任何行、不改动任何图片 |

## 关于这个仓库

- `src/` 是 vendored 的上游应用源码（上游已声明停止维护），本仓库在自己的分支上做了维护性修改与功能补充。
- **相对上游改了哪些文件、为什么改**，全部登记在一份清单里，可随时自查：

  ```bash
  bash tools/diff-vs-upstream.sh
  ```

  它会把仓库里的 `src/` 与上游快照逐文件对比，并校验所有偏差都落在"已知偏离清单"内 —— 只要它不报错，改动就恰好是清单里那些。

- `patches/` 里是一份"给人看的"补丁存档（不参与构建 —— 构建用的就是 `src/` 里的文件）。
